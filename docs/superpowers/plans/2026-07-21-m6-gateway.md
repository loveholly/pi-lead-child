# M6 网关 Implementation Plan

> 依据 docs/DESIGN-GATEWAY.md §0-§3。REQUIRED SUB-SKILL: superpowers:executing-plans。
> 每阶段 TDD + commit。真实验收需要用户提供 BotFather 的 `bf_` token（末尾唯一人工介入点）。

## Phase A: aish 适配器（优先）

1. **协议类型** `src/gateway/aish-protocol.ts`：从 slack-to-agents `src/protocol/types.ts` 复制（已核对 protocol_version 1 全量 shape）。
2. **适配器** `src/gateway/aish-adapter.ts`：
   - 状态机照抄 ws-client.ts 语义：auth 首帧（5s 双侧超时）、应用层 ping/pong（30s 发/15s 等）、退避 1→60s、`AUTH_FAILED/AUTH_TIMEOUT` 致命停止；
   - WebSocket 用 Node 22 原生 client，`makeWebSocket` 可注入（测试用 ws 包对接假服务器）；
   - 出站动作带 request_id + pending map（ACK 10s 超时）；
   - `StreamHandle`：256 字符/100ms 缓冲 flush，懒 stream_start（ACK 取 stream_ts），≤4 条未 ACK 在途，失败降级 send_message；
   - 入站 event → `add_reaction(eyes)` + 回调 daemon；timeouts 全部可注入。
3. **假 aish 服务器** `test/fake-aish.ts`（ws 包）：auth 校验、event 下发、ACK 回复、ping、可注入故障（auth 失败/断线）。
4. **daemon 集成**（server.ts）：
   - env `PLC_AISH_URL`/`PLC_AISH_TOKEN` 齐全即启动适配器，connected 后 upsert bindings（kind='aish-slack'）；
   - **runTurn 增加 origin**：aish 来源的回合，delta 同时流向 aish StreamHandle（socket 客户端保持广播观察）；busy 时 aish 消息走 steer；
   - 消息前缀标注来源（`（来源：Slack ...）`）；
   - 通知：aish 已连接时 blocker/child 完成经 send_message 推到最近活跃 thread。
5. 测试：握手成功/失败、event→lead(stub)→流式回帖全链路、ping 超时重连、断线重连退避。

## Phase B: paired 平面（inbound，桌面/手机端路径）

1. **Schema**：`pairings`（code_hash/expires/scopes/kind/name/status）+ `bindings`（token_hash/kind/external_subject/scopes/status/last_seen）。
2. **DAO** `src/store/gateway.ts`：createPairing（`PLC-XXXX` 码，去混淆字母表，TTL 15min，只存 sha256）、redeem（原子：校验+建 binding+发 token 只存哈希）、authenticate（token→binding，更新 last_seen）、revoke。
3. **TCP 网关**（`ws` 包，`PLC_GATEWAY_PORT` 默认 46600，绑 127.0.0.1 可配）：
   - `POST /v1/paired/redeem`（唯一免鉴权 HTTP）+ WS `/v1/paired/events`（Bearer 鉴权在 upgrade 前）；
   - WS 上说现有 daemon 客户端协议（chat/delta/tool/notice/steered/turn_end/hello）——桌面/手机端与 CLI 同构。
4. **CLI**：`plc pair new --name X --kind desktop|companion`、`plc pair list`、`plc pair revoke <id>`（owner 平面，直连 DB）。
5. 测试：配对全流程（码→redeem→token→WS chat）、过期码拒绝、revoke 后 401、错误 token 拒绝。

## 验收
