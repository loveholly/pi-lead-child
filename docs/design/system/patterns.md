# 系统层：交互和信息结构

本文的规则不随主题变化。任何主题都要遵守。具体的颜色、字号、样子写在主题文件里（当前是 [`../themes/default.md`](../themes/default.md)）。

> 状态：初稿（2026-10-26）。规则编号见 [`../README.md`](../README.md)。

## P1 会话列表稳定

会话列表是用户读得最多的地方。用户正在读的内容不能被别的东西推开或挪动。

| 编号 | 规则 | 理由 |
|---|---|---|
| P1.1 | 只有两种情况可以让列表变高：在最底下追加新内容，以及最后一轮回复在流式输出。 | 用户读到一半时，内容不会跳。 |
| P1.2 | 历史里的卡片不在原地展开。要看更多，用锚定浮层（P2）。 | 原地展开会把下面的内容推走。 |
| P1.3 | 卡片原地更新状态时，收起态的高度不变（P4.1）。 | 状态变化很频繁，每次都变高，列表就会一直抖。 |
| P1.4 | 不在视口上方插入或删除行。必须删除时，用滚动锚定，保证看得见的内容不动。 | 同上。 |
| P1.5 | 实时数据还没取到时，用和最终内容一样大的占位块（`Placeholder`），取到后不变高。 | 同上。 |

## P2 锚定浮层

所有「点开看更多」都用同一种浮层。组件是 `AnchoredPanel`（`packages/components/src/display/AnchoredPanel.tsx`）。

| 编号 | 规则 |
|---|---|
| P2.1 | 浮层从被点的那张卡片的原位置撑开：左上角不动，向下展开。下方放不下时向上展开。 |
| P2.2 | 浮层盖在后面的内容上，列表不变高，后面的内容不被挤开。 |
| P2.3 | 触发方式：点卡片的空白处，或者点卡片头部。卡片上的按钮各做各的事，不打开浮层。 |
| P2.4 | 收起方式有四种，都要支持：点头部右边的收起图标；再点一次头部；点浮层外面；按 Esc（web）或返回（Android、iOS）。操作执行完以后，浮层也自动收起。 |
| P2.5 | 点浮层外面时，这一下同时作用在被点的东西上：点到另一张卡就直接打开那张，点到输入框就直接聚焦，不用点两次。 |
| P2.6 | 列表滚动时，浮层跟着它的卡片一起移动，不因为滚动而收起。 |
| P2.7 | 浮层有最大高度。内容超出时在浮层里滚动，滚到头也不带着页面一起滚。 |
| P2.8 | 同一时间只开一个浮层。 |
| P2.9 | 浮层打开时焦点移进浮层，收起后焦点回到卡片。 |
| P2.10 | 浮层开着时对象的状态变了，就原地更新浮层的内容，不让浮层突然消失。 |
| P2.11 | 手机宽度和 iOS 上换成其他形式，见 P13.2。 |

## P3 收起和展开

| 编号 | 规则 |
|---|---|
| P3.1 | 会话里的卡片分收起态和展开态。收起态固定高度，展开态在浮层里（P2）。 |
| P3.2 | 收起态显示什么、展开态显示什么、收起态有几行，由主题决定，主题文件里每种卡都要写清楚。系统层只要求：收起态的高度在画出来的那一刻就确定。 |
| P3.3 | 低频操作不放在收起态里。 |
| P3.4 | 展开态里可以再分一层「详情」，例如依据和检查项。详情也在浮层里展开，不改变浮层外的布局。 |

## P4 原地更新、合并和折叠

| 编号 | 规则 | 理由 |
|---|---|---|
| P4.1 | 一个对象只有一张卡。对象可以是工单、外部消息、介入请求、主人操作。对象有新事件时，原地更新那张卡，不另开一张。 | 同一件事出现几张卡，用户分不清哪张是当前状态。 |
| P4.2 | 连着的同类项合成一项，并写件数。例如连续 3 次失败，或者同一次处置的几件事。 | 减少重复，突出变化。 |
| P4.3 | 一组同类条目最多露出 3 条，其余的写成「更早的 N 条」。 | 控制密度。 |
| P4.4 | 结束的卡片过一会儿收成一行，变成结束行（P9.4）。卡片在视口里时不折叠，等它离开视口再折叠，或者用滚动锚定（P1.4）。 | 结束的事不需要占地方，但折叠不能挪动用户正在看的内容。 |
| P4.5 | 卡片锚定到促成它的那条消息时，排在那条消息的正下方，不按时间插到别处。 | 让因果关系一眼可见。例如「你说了『可以』，Fairy 据此取消了 #104」。 |

## P5 操作和决定

| 编号 | 规则 |
|---|---|
| P5.1 | 一个区域最多一个主按钮，它就是推荐的那个决定。 |
| P5.2 | 按钮的顺序：主操作、其他选择、退出（例如「先不管」）。按钮的轻重和排列方向由主题决定。 |
| P5.3 | 危险操作在原地再确认一次：确认行替换原来的操作行，不弹窗。确认的文字来自操作注册表。 |
| P5.4 | 操作进行中：按钮文字写「正在……」，同组的其他按钮停用。失败时，在操作行下面写原因，按钮恢复可用。 |
| P5.5 | 操作完成后，卡片原地变成新状态（P4.1），浮层收起（P2.4）。 |
| P5.6 | 自动做完的事有撤回窗口时，写出剩余时间。到期后撤回按钮消失，卡片写明结果。 |
| P5.7 | 每个调后端的控件都是一个操作，有两个入口：UI 调的 HTTP 路由，和一个 Lead 工具。两个入口调同一个函数，「现在能不能做」也由同一个函数判断。权限分四档：`user_only`、`lead_allowed`、`delegated`、`user_direct`。详见 `AGENTS.md` 的 UI Actions。 |
| P5.8 | 现在不能做的操作，按钮停用，并写明原因，例如「已经到点」。原因来自上一条说的那个函数。 |

## P6 信息层次

| 编号 | 规则 |
|---|---|
| P6.1 | 一块内容最多分三种角色：**主内容**（对方的话、事情本身）、**结论**（Fairy 的判断、一句话结果）、**辅助**（时间、来源、依据、计数）。每种角色的字号和字重由主题固定。 |
| P6.2 | 一张卡只有一个结论。 |
| P6.3 | 关键的数字和事实要突出，例如「还剩 11 条未确认」。 |
| P6.4 | 元信息合成一行：来源、人、时间、状态。 |
| P6.5 | 用位置和字重区分主次，不靠颜色区分。 |

## P7 状态

| 编号 | 规则 |
|---|---|
| P7.1 | 状态的语义分五类：**等你**（要你处理、要你确认）、**进行中**、**完成**、**已结束**（取消、不处理、已在别处处理）、**失败**。每种对象的状态都映射到这五类之一。状态的写法由主题决定。 |
| P7.2 | 当前状态从 `TicketSummary` 和对应对象的 DTO 来。`items.stage` 是工单生命周期的唯一依据（`AGENTS.md` Core Invariants）。 |
| P7.3 | 历史事件的文字只描述那次事件，不能暗示一个和当前不同的状态。 |
| P7.4 | 状态显示在卡片的固定位置，同一种卡总在同一个位置。 |
| P7.5 | 快照数据（Lead 画卡那一刻的值）写明时间，不做「还在进行」的动效（P12.4）。 |

## P8 作者和信任

每张卡都有作者：**系统**或 **Lead**。和安全、授权有关的内容，Lead 只能引用，不能自己写。这样 Lead 画不出一张假的回执，也写不出和按钮不一致的命令。

| 编号 | 规则 |
|---|---|
| P8.1 | 只能由系统画：代你操作的回执和「不是我」，审批和决定请求的卡片外壳，没有回答的占位，后台处理记录。 |
| P8.2 | Lead 可以画：它自己的回答和结论、它起草的回复、它建的事项卡（状态靠绑定），以及任何信息卡。 |
| P8.3 | 只能引用、不能手写：别人说的话，要审批的命令原文，操作的后果说明（来自操作注册表），改动前后的对比。敏感对象（例如主人操作）Lead 只能给 id，内容由 App 按用户的权限渲染。 |
| P8.4 | 系统卡里可以给 Lead 留槽位，例如外部消息卡里 Fairy 的结论和草稿、介入请求的回答。槽位里只能放文字和 Markdown，不能放按钮。 |
| P8.5 | 决定请求的选项由系统给时，Lead 只能加「推荐」标记，不能改选项和代价说明。 |

## P9 通用卡片模式

新卡片先问：它是哪个模式的一个实例？下面每个模式只规定信息槽位，样子由主题决定。

| 编号 | 模式 | 槽位 | 实例 |
|---|---|---|---|
| P9.1 | **决定** | 标题（在做什么、要你定什么；可加一行来源）+ 选项（单选或多选，每项有名字、代价说明、推荐标记，可加自由输入）+ 操作组 | child 的决定请求；Fairy 问你换哪个模型重发；改提醒的时间；设优先级 |
| P9.2 | **审批** | 头部（状态、谁要做什么、等了多久）+ 内容本身（原样引用，P8.3）+ 后果 + 操作组（拒绝、扩大授权、授权这一次） | child 要跑命令；Fairy 要替你往外发消息；Fairy 要改常设指令；记忆切换；设备配对；改规则被外部内容拦下以后的确认卡（2026-10-27，统一的消息事件工单 09） |
| P9.3 | **外来消息** | 头部（来源、人、时间、状态）+ 对方的话（引用）+ Fairy 的结论和草稿 + 操作组 | Slack、邮件、GitHub 评论。来源只体现在头部的图标和名字上 |
| P9.4 | **结束行** | 状态标记 + 对象 + 一句结果 + 时间 + 展开 | 所有已经结束的卡：已解决、已回复、已授权、已拒绝、已取消 |
| P9.5 | **事项** | 前导（一个短值，例如日期）+ 正文（标题、剩余时间）+ 展开后的操作 | 提醒、日程节点、截止日期 |
| P9.6 | **注脚** | 挂在一条消息下面的一行：做了什么 + 操作 | 代你操作的回执（P4.5） |
| P9.7 | **缺席占位** | 本该有内容的地方，画一个空轮廓 + 原因 + 可以做的事 | 没有回答；回复说到一半被打断（P10.2） |
| P9.8 | **记录块** | 一段时间内后台处理掉的几件事：时间 + 来源和处置 + 摘要 | 后台处理记录 |
| P9.9 | **系统信息行** | 左对齐一行：发生了什么 + 时间（2026-10-28 用户：居中换行太难看）。太长时截断，全文在锚定浮层里 | 只记录的主人操作；后台巡检连续失败 |
| P9.10 | **同类合并** | 一组同类的事：标签 + 做了什么 + 件数和时间段 + 展开；展开后一件一行。例外（失败的、要你处理的）不进组，单独写在组的前面（2026-10-28） | 你允许的几次写入；Lead 卡片里「已加 12 条评论」「跳过 3 件」；连着做的几次设置修改 |

## P10 失败和降级

| 编号 | 规则 |
|---|---|
| P10.1 | 失败出现在它本来的位置。例如没回答的那一轮，就在那一轮的位置画缺席占位（P9.7）。 |
| P10.2 | 流式回复被打断时，保留已经说出的部分，后面接缺席占位，不整段删掉重来。 |
| P10.3 | 写清可以重试什么。例如引用用户那句话，按钮写「重发这句」。 |
| P10.4 | 系统会自己重试的失败，不给按钮，只写下次什么时候再试。 |
| P10.5 | genui 卡片显示不了时，只显示 `fallbackText`。 |
| P10.6 | 引用的原文取不到时，显示占位和「原文暂时取不到」，不让 Lead 补写。 |

## P11 genui

| 编号 | 规则 |
|---|---|
| P11.1 | genui 用的就是 App 自己的组件。每个节点类型对应 `packages/components` 里的一个组件，不做 genui 专用的组件。 |
| P11.0 | 组件分三层，Lead 从上往下选（用户 2026-10-27 定）：**对象组件**（账本里的一个对象，只给编号，内容、状态和操作由系统实时取，例如提醒、外部消息卡、介入请求、工单）→ **模式组件**（P9 的一个模式，版式固定，只填参数）→ **原子积木**（不属于任何模式的长尾）。对象组件和模式组件都用积木搭成，系统卡和 genui 共用。命名按对象类型或信息的形状，不按业务场景：没有「日历卡」「航班卡」，只有「事项」。 |
| P11.2 | Lead 可以自由组合：积木和现有组件随意嵌套、排列；强调等级；分区和图块的色调；从系统的语义图标里选图标；收起态的行数。 |
| P11.3 | 唯一的硬约束是布局稳定：Lead 能选的都是枚举值，每个值对应一个确定的尺寸；内容都有长度上限；会变大的只有展开态，而展开态在浮层里。 |
| P11.4 | 具体的颜色、字体、字号、圆角、阴影、边框、装饰、动效，由 App 和主题决定。Lead 碰不到。 |
| P11.5 | 动效挂在组件的行为上，不由 Lead 选（P12.2）。 |
| P11.6 | Lead 只在对象上确实有下一步时才放按钮。 |

## P12 动效

| 编号 | 规则 |
|---|---|
| P12.1 | 常用动效包成组件，放在 `packages/components/src/motion/`，系统界面和 genui 共用：`Grow`（撑开）、`Reveal`（内容淡入）、`StateFade`（状态过渡）、`Tick`（数字切换）、`Fold`（折叠成一行）、`Settle`（新卡片到达）、`Press`（按压反馈）、`Indeterminate`（不确定进度）、`Placeholder`（占位）。 |
| P12.2 | 动效挂在组件的行为上。Disclosure 自动带「撑开」，Binding 的值变了自动带「状态过渡」。 |
| P12.3 | 动效只用于用户触发的展开、收起、切换，以及新内容到达。唯一的例外是 P12.8。 |
| P12.4 | 快照数据不做「还在进行」的动效：不转圈，不闪烁，不做假进度。进度未知时写「进度未知」。 |
| P12.5 | 任何动效都不能挪动列表里的其他内容（P1）。 |
| P12.6 | 时长和曲线是主题的 token。组件只引用档位名。 |
| P12.7 | 系统开了「减弱动态效果」时，全部动效退成瞬间切换，或者只保留透明度变化。 |
| P12.8 | Lead 的形象表示 Lead 此刻的状态，不是装饰。它是唯一可以在用户没有操作时动的东西，而且只在表示「现在」的那一个上动：左栏头部（或顶栏）的那一个，和会话里最新的那条回答。更早的消息上的形象是静止的（P12.4）。缺省的系统素材只在思考和处理时动；隐藏的 FairyEye 模式（只有用户发 `/fairyeye on` 才打开）待机时也慢慢转。用户自己上传的动图照原样播放，是用户的选择。状态不能只靠动作表达，旁边要有文字或无障碍标签（P13.3）。（2026-10-28 用户定，画布 <https://claude.ai/artifact/V8ExdMkVErJTEnesx5ms6F>；同一天晚上用户定：FairyEye 改成隐藏模式，缺省用系统素材，可以上传。） |

## P13 平台适配和可及性

| 编号 | 规则 |
|---|---|
| P13.1 | 组件的接口三端一致：每个组件一个 `Xxx.types.ts`，三端的 props 相同。实现可以按平台不同（见 `packages/components/README.md` 的「三端一致的保证」）。 |
| P13.2 | 锚定浮层在三端的形式：网页上从卡片原位置撑开；Android 和手机宽度的网页上是从底部升起的面板；iOS 上用 SwiftUI 的 `Popover`（Expo UI），从卡片的位置弹出，iPhone 上也保持浮层的形式，背景用系统的玻璃材质。长按卡片出系统菜单（`ContextMenu`），菜单项就是卡片上的操作。（2026-10-26 用户定。Expo UI 57 没有「面板从元素变形出来」的接口，见 `.scratch/genui-catalog-v3/research-icons-expo-ui.md`。） |
| P13.3 | 状态不能只靠颜色表达，每个状态都有文字或无障碍标签。 |
| P13.4 | 文字和背景的对比度至少 4.5:1，图标和图形至少 3:1。字号最小 11。 |
| P13.5 | 手机上可以点的区域至少 44pt。 |
| P13.6 | 支持键盘：Tab 能走到每个控件，Esc 能收起浮层。 |
| P13.7 | 系统材质（例如 iOS 的玻璃）是平台的实现，不属于主题。系统开了「降低透明度」时，玻璃退成主题的实色表面。 |

## P14 文案

| 编号 | 规则 |
|---|---|
| P14.1 | 用白话写。能用 Markdown 的地方就用 Markdown：列表、表格、行内代码。 |
| P14.2 | 时间用短格式，例如「10-29 14:00」「周四 14:00」，用等宽字体；相对时间写「还有 3 天 1 小时」「等了 4 分钟」。 |
| P14.3 | Lead 的名字统一从 `useLeadName` 取，不写死。 |
| P14.4 | 不加推测性的「下一步」按钮，不加多余的标签。 |
| P14.5 | 按钮文字写动作和对象，并跟着选中项变化，例如「改到周五 14:00」。 |

## P15 设置页的结构

| 编号 | 规则 |
|---|---|
| P15.1 | 设置页由分区和行组成，和会话卡片共用同一套间距、字号和组件。 |
| P15.2 | 每一行写清楚改了以后什么时候生效：立即生效，或者要点「保存」。 |
| P15.3 | 不可撤回的操作放在单独的危险区，就地确认（P5.3）。 |
| P15.4 | 授权、密钥、配对这类 `user_direct` 操作，Lead 调用时只得到「去哪里点」的指引，设置页上要有那个入口。 |
| P15.5 | 设置页上的每个控件都是一个操作（P5.7）。 |

> 设置页现在的样子还没有对照本文审过。审完以后补充具体的行类型（开关、选择、输入、只读信息、危险区）。

## P16 右侧面板

打开一个对象的完整内容（工单详情），或者一块常驻的区域（视图），用右侧面板。组件是 `SlidePanel edge="right"`（`packages/components/src/motion/Motion.tsx`）。本节照工单详情现在的做法写（2026-10-30，视图面板复用它，`.scratch/custom-views/spec.md` D2）。

| 编号 | 规则 | 理由 |
|---|---|---|
| P16.1 | 桌面上，右侧面板是工作台的一栏：和会话栏平分左栏以外的宽度，最宽 640（`THREAD_LAYOUT`）。会话栏用 `LayoutTransition` 平滑地变窄。 | 面板里的内容要和会话一起看，不盖住会话。 |
| P16.2 | 右侧只有一个位置：工单详情和视图面板不同时打开。打开一个时，另一个收起。 | 三栏已经是桌面宽度的上限，第四栏会把会话挤得太窄。 |
| P16.3 | 手机宽度上，右侧面板盖在整个内容上（`modal`），并作为对话框暴露给无障碍服务。 | 窄屏放不下两栏。 |
| P16.4 | 面板只由用户打开：点顶栏的入口、工单行或工单引用。系统和 Lead 不自己打开面板（2026-10-16 用户定）。 | 面板会改变会话栏的宽度，不能在用户没有操作时发生（P1）。 |
| P16.5 | 面板的头部：标题，右边是关闭按钮。 | 和工单详情的头部一致。 |
| P16.6 | 滑入、滑出用 `SlidePanel` 自带的动效（260、220，和 M-6 同档）。 | 动效挂在组件上（P12.2）。 |
| P16.7 | 视图面板里的控件按「视图」分组。只有一个视图时不显示 tab；有两个以上时，头部下面一行是分段选择（`SegmentedControl`），不跟着控件滚动。缺省的视图排第一，叫「常用」（2026-10-30 用户定）。 | 大多数人只需要一页；分类是用户要了才有的东西，不该先占一行。 |
